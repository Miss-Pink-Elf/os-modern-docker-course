### Ответы на вопросы:
**1. Зачем в Ч.1 использовался `--link` и почему в Compose он не нужен?**  
`--link` — это устаревший механизм ручной связки контейнеров. Он прописывает IP-адрес и имя одного контейнера в файл `/etc/hosts` другого, а также прокидывает переменные окружения. В Docker Compose он не нужен, потому что Compose автоматически создает единую изолированную сеть (bridge) для всех сервисов проекта. Внутри этой сети работает встроенный DNS-сервер, который позволяет контейнерам обращаться друг к другу по имени сервиса (например, `rocketcounter` находит `redis` просто по хосту `redis`).

**2. Чем отличается `image` от `build` в Compose?**
`image: <name>` — инструктирует Compose использовать готовый образ из реестра (например, Docker Hub) или локальный, если он уже скачан.
`build: <path>` — инструктирует Compose собрать образ самостоятельно из Dockerfile, который находится по указанному пути (например, `build: ./app`).

**3. Почему нельзя масштабировать сервис с публикацией фиксированного порта на одном хосте? Перечислите способы обойти это ограничение.**  
На одном сетевом интерфейсе хоста конкретный порт (например, 8085) может слушать только один процесс. Если запустить вторую реплику с тем же портом, Docker выдаст ошибку `port is already allocated`.  
![](Pasted%20image%2020261115120158.png)
**Способы обойти:**
1. Использовать динамические порты (`"0:5000"`), чтобы Docker сам назначал свободные порты.
2. Использовать обратный прокси (Nginx, Traefik) перед репликами, который слушает один порт и распределяет трафик между ними.
3. Использовать оркестраторы (Docker Swarm, Kubernetes), которые имеют встроенные механизмы балансировки нагрузки.

**4. Что делает `docker compose down -v` и чем отличается от `down` без `-v`?** `docker compose down` — останавливает и удаляет контейнеры, а также удаляет созданную для них сеть. Данные в томах сохраняются.
`docker compose down -v` — делает то же самое, но **дополнительно удаляет все тома (volumes)**, привязанные к сервисам. Все данные (например, база данных Redis) будут безвозвратно утеряны.

**5. Как в Compose обеспечивается сетевое имя сервиса для обращения из другого сервиса?**  
Docker Compose по умолчанию создает единую сеть для всех сервисов. При создании контейнера ему назначается сетевой алиас, совпадающий с именем сервиса в `docker-compose.yml`. Встроенный DNS-сервер Docker автоматически разрешает это имя в актуальный IP-адрес нужного контейнера внутри сети.
